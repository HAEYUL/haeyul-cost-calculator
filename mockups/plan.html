🔐 구현 방식: 로그인 2종류 + 권한 분리

앱은 하나 그대로 두고, 들어오는 비밀번호에 따라 "매니저 출입증"과 "관리자 출입증"을 다르게 발급합니다. 화면만 숨기는 게 아니라 DB(서버)에서도 막아요.

매니저
매장 버튼 + 지금 쓰는 매장 비밀번호 4자리 (그대로)
→ 그 매장 1곳의 매니저 출입증 발급
→ 메뉴: 거래명세표 등록 · 실재고 조사 · 파출 관리 3개만
→ 송금 여부, 결제, 미수금, 결산, 원가는 보이지도, 읽히지도 않음
메인 관리자
🔑 메인 관리자 + 관리자 비밀번호 (새로 만듦, 6자리 이상)
→ 4개 매장 전체 관리자 출입증 한 번에 발급
→ 위쪽 탭으로 매장 전환 (다시 로그인 없음) · 지금 쓰는 메뉴 전부 그대로
→ 송금완료 체크, 세무 출력, 주민번호 전체 보기는 관리자만
→ 관리자로 들어오면 결산 비밀번호도 다시 묻지 않음

무엇을 볼 수 있나요

자료매니저 (자기 매장만)메인 관리자 (4개 매장)막는 방법
🧾 거래명세표 입력입력·수정전체관리자가 확정하면 매니저 수정 잠금
📦 실재고 조사입력·수정전체재고 금액·원가는 매니저 화면에 표시 안 함
👷 파출 근무 (날짜·이름·주민번호·시간·일당·계좌)입력·수정전체주민번호 암호화, 매니저는 가려서 표시
💸 파출 송금완료 기록✕ 안 보임체크·취소별도 표에 저장 → 매니저 출입증으로는 DB에서 아예 못 읽음
🤝 거래처 결제 · 미수금 · 잔액✕전체DB 권한 = 관리자 전용
📊 매장운영결산 · 🍲 레시피·원가 · 리포트✕전체DB 권한 = 관리자 전용
🖨️ 세무 출력 (주민번호 전체)✕출력서버에서 관리자 확인 후에만 복호화
🔒 안전장치
· 관리자 비밀번호 5회 틀리면 5분 잠금 (지금 매장 비밀번호와 같은 방식)
· 관리자 비밀번호는 처음 한 번만 설정: 해율 매장 결산 비밀번호로 본인 확인 후 설정
· 송금완료 체크·취소 시 날짜와 시각 기록, 수정 이력 보관
♻️ 기존 자료·비밀번호
· 매장 비밀번호 4자리는 그대로 (매니저용으로 사용)
· 지금까지 입력한 장부는 전혀 바뀌지 않음
· 문제가 생기면 바로 원래대로 되돌리는 SQL을 함께 준비
🛠️ 만드는 순서
1) 관리자 로그인 + 4개 매장 전환
2) 매니저 메뉴 3개로 제한 + DB 권한 분리
3) 파출 관리 (매니저 입력)
4) 송금 관리 · 세무 출력 (관리자)
